Case Study 01 / Portfolio architecture

Building a full-stack portfolio.

A self-initiated case study on how a set of separate HTML pages became one connected product with a real API, tests and a shared design system. It is a concept project, not client work.

Role: Designer & DeveloperTools: HTML · CSS · JavaScript · Node.jsFocus: Architecture & UX

01 / The challenge

Make separate projects feel like one product.

Individual HTML pages drift apart: different navigation, copy-pasted styles, fake buttons that don't actually do anything. The goal was to rebuild the portfolio so the projects share one design system, one data layer and one back end, so an order placed in the store really shows up in the analytics dashboard.

02 / Architecture

One API client, two ways to answer

Pages never call fetch directly. They use api.js, which checks whether the Node server is reachable. If it is, requests go over HTTP. If not (for example on GitHub Pages), the same endpoints are emulated in the browser with localStorage, using the exact same business code.

03

Never trust the client

The cart in the browser only stores item IDs and quantities. When you check out, the server looks up the real prices, checks stock, applies promo rules and calculates the total itself. A tampered request can't buy a ₱1,490 hoodie for ₱1. There's an automated test for exactly that.

04

Shared logic, written once

Pricing, validation and analytics live in public/js/shared/ as pure functions. The browser uses them for instant feedback, the server uses them as the authority, and the tests exercise them directly. Fixing a bug once fixes it everywhere.

05

Depth with restraint

Black and yellow keep the interface calm. Depth comes from two techniques: CSS 3D tilt on cards, and a small hand-written canvas engine for the hero and the fries carton. Both switch off for visitors who prefer reduced motion, and the canvas pauses when off-screen to save battery.

06

What testing found

Writing integration tests exposed a real bug: stock was checked per cart line, so adding the same product on three lines could oversell it. The fix aggregates quantities per product first, and the test now guards against it.

Reflection

A consistent portfolio is more than a visual theme. Clear structure, shared code, honest data and accessible interactions matter just as much. Next steps are a real database, user accounts, and browser-based end-to-end tests.
